# ui-ascii

A playable terminal front end for agent-kernel: you are `@`, find the exit `E`, and mind the traps `H`.

It is reachable from the `ak` CLI and the MCP server, so any harness can create a level and show it:

```bash
node packages/adapters-cli/src/cli/ak.mjs create --room "size=small;count=3" \
  --delver "count=1;affinity=wind;motivation=exploring" \
  --hazard "affinity=corrode;expression=emit;proximityRadius=1;mana=one-time:30" --out-dir /tmp/traps
node packages/adapters-cli/src/cli/ak.mjs play --dir /tmp/traps            # play it here
node packages/adapters-cli/src/cli/ak.mjs play --dir /tmp/traps --json     # { screen, status, turns, launch, warnings? }
```

Over MCP the same request ("create an ascii UI filled with <affinity> traps", for any of the ten affinities) is `ak_create` with hazards of that affinity, then `ak_play_ascii` with that call's `runId`: it returns the board as text plus the `launch` command for the interactive game. `ak play` runs this package as a separate program; adapters-cli never imports it.

**Play through Claude Code.** Opened in this repository, Claude Code already has the MCP server (the root `.mcp.json`, enabled with the game tools pre-allowed in `.claude/settings.json`) and the game commands in `.claude/skills/`: `/game-new` authors a level from a description with `ak_create` and shows it, `/game-play` plays it turn by turn as a live game (`ak_play_start`, then `ak_play_act`, `ak_play_switch`, `ak_play_order`, `ak_play_advance` and `ak_play_end`, which keep the game in a file through `--session` below), `/game-watch` steps through a recorded run, `/game-save` and `/game-load` keep a game in a capture file, `/game-recap` narrates a run, and `/game-terminal` gives the command for the interactive game. The `game-master` skill holds the rules Claude follows while doing it. Claude is a front end like this one: every move goes through `ak_play_ascii`, so the screen it shows is this package's.

```bash
pnpm run play:ascii                                 # bundled levels, in order
pnpm run play:ascii -- --level long-way-round       # start at a bundled level
pnpm run play:ascii -- --run <dir>                 # play a level `ak create --out-dir <dir>` generated (rooms + corridors)
pnpm run play:ascii -- --sim-config <p> --initial-state <p>
pnpm run play:ascii -- --keys "ddss" --no-color     # scripted: apply keys, print, exit
pnpm run play:ascii -- --keys "ddss" --json         # scripted, as { ok, level, turns, status, screen, warnings? }
pnpm run play:ascii -- --no-fog                     # debug: see the whole map
pnpm run play:ascii -- --record game.json           # on quit, save the played commands
pnpm run play:ascii -- --realtime 500              # a turn passes every 500 ms while you wait (t toggles)
pnpm run play:web                                  # play in a browser tab at http://localhost:8765 (--port to change)
pnpm run play:web -- --lan                         # ...and from a phone on the same Wi-Fi
pnpm run play:ascii -- --replay game.json           # re-run a saved game, then keep playing
```

**Party and names.** A level may hold several actors authored `user_controlled`: the party. Tab (outside a list) plays the next one, for free; the screen lists the party (`Party: [D1 hero-1]  D2 hero-2 (exploring)`, each member's motivations beyond `user_controlled`) and everyone in sight by a short label with its motivations (`In sight: W1 card_warden_1-1 (defending)`); a trap or actor whose lasting affinity ran out of mana is drawn dimmed, has no field, and is listed `H1 t (off until mana is full)` until its pool is full again (#412), or `(off: upkeep 5 > max mana 4)` when full mana can never pay it (#454; the same on your own slot line); an actor soaked by a `soak`-trait affinity is listed `(soaked N)` with the turns it stays soaked, and the seated actor's vitals line ends `soaked N` (#420: each move costs one more stamina while soaked); an actor that leaves during the last turn gets one event line, `D3 pal-1 left by the exit` or `W1 guard was defeated` (#428: anyone on your side wherever it is, others only when the seat could see them; `view().departures`); the target panel names the target's motivations too. Under fog, what an actor in sight is about must be revealed (#416): an unrevealed one shows `(?)` in place of its motivations, and one revealed at level N shows its vitals and affinities with any value above N as `N+` (`view().actors[].revealed`, set by the play session from core). Party members are always known. Labels are the role's letter and the actor's place in id order (`D`elver, `W`arden, `H`azard, `B`arrier, `R`esource), so they never change during a game. Fog follows the seated actor; each party member remembers what it has seen. **The battle (#463).** For the turn of a cast, by anyone, each floor cell on its path shows an arrow, `>` `<` `^` `v` or `/` `\` (away from the caster for a push, back toward it for a pull), tinted with the affinity's palette colour; actors, traps and walls keep their glyphs, and the next turn redraws floor. The message line names what a hit did: `You hit W1 with decay push: HP −8`, and each hit on you, `W1 hits you with growth push: HP +3`. It also names what hit whom and what regen gave back (#410), e.g. `W1 DU 10/10 (−1 +1)` (you first, as `You`; only vitals that were hit; at most three), so a hit that regen cancels is still seen landing; this is `view().vitalChanges`, from core's turn record. The paths, arrows and changes are the play session's `view().casts` (core's turn records each cast; arrows and tints come from runtime render), so under fog only the cells you see are drawn. Seating, labels and per-member memory are the play session's (`switchTo`, `act(command, { actorId })`, `view().party`); this package only draws them. Motivations are listed, never encoded in board glyphs. Companions and wardens cannot be seated.

**Defeat (#488).** When the player's actor is defeated the board is replaced by a skull and crossbones (palette hazard colour), `Defeated by W1 w1's fire push.` (the last cast that landed on you, else the field you stood in; `defeatCause(view)`), and the usual try-again line; the web view serves the same text.

**Battle log (#554).** The last four log lines print under the status line (`T3 You cast decay push and struck W1 warden_1.`), and the phone app's message band lists the whole log, newest first, under `Battle log`. The Annotator derives the entries (casts; takes, naming what they gave, e.g. `You took +10 health from R1 resource_1.`; defeats, naming the cast or the emit field that did it, with what lives on durability reading "destroyed"; exits; no one's vitals, #497), `render/battle-log-lines.js` words them, and `view().battleLog` carries only what the seat may read (its own and its party's, or what a party member can see under fog); this package only draws it.

**Defeats (#490).** A defeat line names its cause (`W1 guard was defeated by D1 hero's decay push`, or `by H1 rot's field`) and an `x` in the hazard colour marks the tile for three ticks (`view().defeatMarks`; `departures[].by`/`position` come from the play session). A resource emptied of its last holding leaves the board and a `*` marks its tile for the same three ticks (a `spent` defeat mark); a defeated actor that still holds something to take is drawn as `R` until it is emptied (`view().lootBodies`).

**Your own character.** `bash scripts/game/playtest.sh <scenario> --character` opens a character screen before the level is built, so you play a delver you configured instead of the scenario's own. It lists all six affinity slots (kind, form, range, intensity, and the slot's mana as a guide: per tick for an emit or draw, per cast for a push or pull, red when above max mana, with the emits' total a tick shown below; every slot you hold starts equipped; an unused slot reads kind `none` at default values, and is not bought), the four vitals (max and regen) and the playable right (`user_controlled`, fixed), with the Allocator's price on every row and your budget at the top (the delver pool the scenario's own hero is built against). `+` `-` change a value (`]` `[` by 5; a kind steps through `none` and every kind), arrows or `wasd` / `hjkl` move, `x` sets a slot to `none`, `r` resets, Enter plays and `q` goes back. A Minions section adds your own minions: pick a role per row (shield, support or striker; none takes one out), and the Configurator derives each one's affinity from yours, as it does for a warden's retinue; they follow you and take your orders, and the Allocator prices each against the same allowance. It refuses a character that is over the allowance, below the viability floor or holds the same affinity and form twice. The first three slots come with a delver; choosing a kind past them buys a slot the Allocator prices, and setting it back to `none` returns it. Nothing is capped except by price: 100 max mana is fine if you can pay for it. The screen writes an ordinary `--delver` spec, the scenario's playable delver is swapped for it, and `ak create` builds and prices the level as usual; the report records the character, so `--open` rebuilds the same game. `node packages/ui-ascii/src/character-cli.mjs --spec "<delver spec>" --budget N --keys "<keys>" --json` scripts the screen. The sheet (`runtime/src/runner/character-sheet.js`) holds the choices and asks the Allocator for every price (`pricing.quoteActor`); this package only draws it and maps keys, so the browser and the phone can send the same intents. Wardens, hazards, resources and levels will get their own sheets. With `--web` the configuration happens in the terminal before play; the phone app has its own touch version (below).

**Analysis console (#500).** `ak play --web --debug` adds a side panel to the browser page for evaluating a level: every actor in full (kind, role, motivations, affinities with range and intensity, vitals with regen, position), the level's seed, action costs and, for a level built by `ak create` (read from `budget-receipt.json` and `price-list.json` beside its sim-config), the budget receipt's status, total, remaining and line items and the price list, an event log of every cast, take, defeat and exit by anyone, and a click on any board tile shows everything on it including the net affinity field. It reads `/debug`, served only with the flag, from the play session's `debugView()`; it never reveals anything in a normal game, and the server prints a DEBUG notice.

**Fields and memory (#479).** Empty floor inside an active affinity field is drawn `:` as well as tinted, so a field shows without colour, for every kind. A delver or warden you have seen stays drawn, dimmed, where you last saw it (`view().lastSeen`, kept per seat by the play session) until you see that cell empty, it is gone, or it hides in dark.

**Inspect (#497).** `v` picks a target in sight (Tab cycles, Enter confirms) and spends one turn looking at it; no mana, the same for every actor. The play session reads the target's vitals, affinities and motivations capped by the reveal level at its tile (at least 1, so a look with no light shows the basics; values above the level read `n+`) and keeps the reading with its age (`view().inspections`, `Inspected W1 warden_1 (2 turns ago): HP 10/10, ...`). A cast's target picker no longer shows the target's state, and a hit on someone else shows only what it did (`W1 DU (−1 +1)`), never their current/max; your own vitals still do. Command: `{"kind":"inspect","params":{"targetId":"W1"}}`. **Watch (#519).** `e` picks a target in sight and begins watching it, or stops if you already do (one turn to begin, none to stop). A watch costs 1 mana a turn per target, paid in core with the other upkeeps, and ends when mana cannot pay it or the target is gone. While the target is in sight its reading is live (`Watching W1 warden_1 (now): ...`, `age` 0, `watched: true` in `view().inspections`); out of sight the last reading stays with its age. Command: `{"kind":"watch","params":{"targetId":"W1"}}`. Mana regen is paid after upkeep, so an actor whose mana regen is at least the upkeep sees the cost refilled within the turn.

**Orders.** Party members and companions on your side can be given a strategy (standing goals and tactics the Actor follows on their own turns): `--commands '[{"kind":"order","actorId":"D3","strategy":{"goals":[{"kind":"follow","target":"D1"}]}}]'` costs one turn, and `{"kind":"advance","ticks":10,"until":"orders_done"}` lets the level run (until `orders_done` or `contact`). The screen lists who is under orders and how it is going (`Orders: D3 follow hero-1  D4 defeat W1 (searching)`); `--json` adds `orders`. In the terminal, `o` gives the same orders from the keyboard. Orders, progress, who may be ordered and `advance` are the play session's (`order`, `advance`, `view().orders`, `view().orderable`); what a strategy means is the Actor's.

**Live games across calls.** `--session <file>` keeps one game in a file for a caller that is not at a terminal: it replays the file if it exists (the file names its level), applies `--actor <id|label>` (seat), `--commands '<json array>'` (structured commands, labels allowed) and `--keys`, then saves the file. With `--json` the result adds `active`, `party`, `orders` (when any), `inSight`, `results` and `hud` (one line about the seated actor). `ak play-session` and the MCP `ak_play_*` session tools are built on it.

**Viability floor.** A level loaded from files is played as written. If a delver or warden sits below the viability floor (health, mana and durability each need max 10 and regen 1, which `ak create` applies while authoring), the Configurator's report is printed as `warning:` lines on stderr and returned as `warnings` in `--json`.

**Watching a run.** The same screen also shows a run `ak run` recorded, tick by tick: `--watch --run <dir>` (an `ak run --out-dir`, or an `artifacts/runs/<id>` directory with the run under `run/` and the build under `create/`).

```bash
pnpm run play:ascii -- --watch --run <dir>                     # left/right (or h/l, ,/.) step a tick, [ ] jump to the first/last, q quits
pnpm run play:ascii -- --watch --run <dir> --tick 5 --json      # { ok, tick, maxTick, level, status, screen }
```

Every actor and trap is drawn where the run recorded it at that tick, with no fog (a viewer watches the whole run, not one actor's sight), and the HUD follows the actor the game would seat as the player, drawn `@`. What is on the board at a tick is the runtime run viewer's (`runner/run-viewer.js`): it reads the registry snapshot each tick frame recorded and hands back the play session's `view()` shape, so this package draws it with the same code; nothing is re-simulated. `ak play --watch`, MCP `ak_play_ascii` with `watch: true`, and the `ascii` of `ak tick` / `ak_show_state` are this screen. `--no-help` starts with the key help hidden, in play and in watch.

**Record and replay.** `--record <path>` writes the current level's played commands as a `CapturedInputArtifact` (`source.adapter: "player"`, one `{ tick, actorId, command }` per turn) when you quit or when `--keys` finishes. `--replay <path>` re-runs them on the same level (a bundled level is picked from the capture) and play continues from there; with `--keys` or `--json` it prints the result instead. The simulation is deterministic, so a replay reaches the exact same state; the play session refuses a capture whose commands no longer land on their recorded ticks. The log and the replay are the play session's (`captureInput`, `replayPlaySession`); this package only reads and writes the file.

**Walking breaks even; resting refills faster.** A step costs stamina and stamina regenerates every turn, so plain walking at the default cost never drains it; a turn you don't move is a rest and restores twice the regen (#407), for every actor alike. Wait (`.`) to catch your breath. The rule is core's; this package only shows the bar.

**In a browser.** `--web` (also `ak play --web`, or `pnpm run play:web`) serves the same game on `http://localhost:8765` (`--port <n>` to change) instead of taking over the terminal: open the address, click the page, and play with the same keys. The screen, colours, panels and real time (`t`, `--realtime`) are the terminal's; `q` and Esc only close a panel, so close the tab to stop looking and press Ctrl-C in the terminal to stop the server. It listens on this machine only (`127.0.0.1`) unless you add `--lan`: then it also serves your local network and prints an address such as `http://192.168.1.20:8765` that a phone on the same Wi-Fi can open (anyone on that network can play it while it runs). On a touch screen the page shows buttons: a direction pad with wait in the middle, and the game's other keys. `src/web.mjs` owns it, with Node's own `http` module and no dependencies.

**Turn-based by default; real time is opt-in.** Time passes only when you act, so standing next to a trap costs nothing until you take a turn. `--realtime <ms>` starts real time: every `<ms>` milliseconds without a key, the game takes a wait turn for you, exactly as if you had pressed `.`. `t` switches real time on and off in game (at 500 ms when no `--realtime` was given), and a line under the board says which mode is on. The beat pauses while a panel is open or the level is over. A beat is an ordinary wait turn, so recordings and replays stay deterministic. Interactive play only: `--keys` and `--json` ignore it (#291).

**Fog of war is on.** You see only what is in sight (levels are unlit, so that is close by). Cells you have never seen are `?`, cells you saw before are drawn dimmed with no actors on them (without colour, remembered floor is blank while remembered walls, doors and the exit stay drawn, #284) (until dark covers them out of sight, which makes you forget them), and other actors and traps appear only while in sight. What counts as in sight is core's and the play session's (`createPlaySession({ fog: true })`, `view().sight`); this package only draws it. `--no-fog` (also on `ak play`, and `fog: false` on `ak_play_ascii`) is a debug view of the whole level for tests and level checks, not a way to play.

Colour is on by default in a terminal and uses the application's approved palette (`GAME_COLOR_PALETTE`, via `runtime/src/render/ascii-cell-style.js`): tiles are flat fills like the Phaser board, the player is the user-controlled colour, wardens and delvers wear their role colours, and an actor or trap with an affinity is filled with that affinity's colour. Floor you can see is tinted by the affinity fields on it, every kind alike: the fill blends toward each field's affinity colour by its strength, after opposite pairs (fire/water, earth/wind, growth/decay, corrode/fortify, light/dark) cancel in core, so a tile shows what actually acts on it (#287). A field that restores a vital (`restores` on `view().field` cells, read from the affinity table for every kind) draws its floor dots toward the palette's resource colour and a harming one toward its hazard colour (#485), and while you stand in someone else's restoring field the HUD says `Field here: restores DU` even at full vitals (your own emit never acts on you, so it is not named). Output that is not a terminal, `NO_COLOR`, or `--no-color` gives plain text; `--color` forces colour. A terminal gets 24-bit colour only when it sets `COLORTERM=truecolor` (or `24bit`), and xterm-256 colour otherwise, because macOS Terminal sets neither and misreads 24-bit codes (#286). Run with `COLORTERM=truecolor` to force 24-bit. Captured output (`--json`, pipes) stays 24-bit.

|---|---|
| arrows · WASD · `h j k l` | move |
| `y u b n` | move diagonally |
| shift + a move key (upper case, or shift+arrow), or `x` then a move | sprint: two tiles in one turn for 3/2 the two steps' stamina, more than regen returns (#437) |
| `.` or space | wait one tick |
| Enter | next level (after escaping) |
| `r` | restart the level |
| `?` | toggle help |
| `q` · Esc · Ctrl-C | quit (in an open panel: close it) |
| `i` | list your affinities; then `1`–`9` equips one into a free slot (or in place of the oldest when every slot is full), or unequips it if it is equipped; Tab moves the `>` highlight, `+` / `-` run the highlighted equipped affinity at one more or less range and `]` / `[` at one more or less intensity (a turn each). Affinities read `fire push r6 ×2`, range then intensity; a slot run lower shows running/held, e.g. `r2/6 ×1/2` |
| Tab | play the next party member (an actor authored `user_controlled`); free. In a list it moves the highlight instead |
| `f` | aim at the nearest actor in sight; Tab picks the next, Enter (or `f`) casts your first equipped push or pull, Esc cancels. A move key aims at a tile instead (`+` on the board; with nobody in sight `f` starts there): Enter casts along the line sight uses and hits the first actor on it (a friendly too; a pull takes a barrier down) or stops at a wall; a push that meets nobody leaves a one-turn field of its kind on its path (light lights it, a harmful kind harms whoever steps in), for the same mana (#461); Tab goes back to the targets |
| `z` | raise a barrier (#460): the tile cursor starts on you with your first equipped push; move keys aim, Enter (or `z`) raises a line of barriers of its kind into empty tiles (as many as its range) that you can walk through, Esc cancels |
| `e` | watch (#519): pick a target in sight, Enter begins a live reading for 1 mana a turn (or stops it) |
| `v` | inspect (#497): pick a target in sight, Enter spends a turn reading its vitals, affinities and motivations (capped by the light on it, at least the basics); the reading stays on screen with its age |
| `1`–`9` | aim with that slot's push or pull (then Tab/Enter as for `f`); an emit or draw slot needs no cast |
| `g` | take loot from a defeated neighbour or an intact resource next to you, without breaking it (with several items, `1`–`9` picks); slot loot opens one more affinity slot |
| `o` | order a party member or a companion on your side: `1`–`9` picks who (skipped when there is only one), then what: follow you, guard you, lead you to the exit, go to the exit, defeat the nearest hostile in sight, hold where it stands for 10 turns, or keep away from hostiles. Giving the order is a turn; the Orders line shows how it goes |

Reaching the exit's approach tile puts you **at the exit**; waiting one more tick steps you through. That is core's exit-dwell rule, not a UI rule. If a warden's casts bring your health to 0 you are defeated: the status line says so, moves do nothing, and `r` restarts the level. Every key that acts costs one turn, a blocked move included: so do an equip, a cast and a take, accepted or refused. Opening, browsing and closing a panel is free. A refusal names core's reason (not enough mana, out of range, nothing equipped). Push and pull are cast; an equipped emit or draw works on its own every turn while its mana upkeep is paid, and the HUD says when it is off waiting for mana. The HUD shows one row per affinity slot (delvers start with 3, wardens with 2); each slot pays its own upkeep and goes off on its own.

## Where it sits

`ui-ascii → runtime → core-ts`. This package imports only its own files, `packages/runtime`, and `node:` built-ins; `tests/architecture/dependency-direction.test.js` enforces it.

| File | Owns |
|---|---|
| `src/cli.mjs` | The terminal: arguments, raw-mode keypresses, redraws |
| `src/keymap.js` | Key → intent (`move`, `wait`, `affinities`, `cast`, `take`, …; and the watch keys). No legality |
| `src/game.js` | Intent → play-session call; level index, move count, last message, the open panel (affinities, target, loot) |
| `src/screen.js` | Lays out the view as text and turns palette hex into ANSI escapes. Board glyphs come from the play session's rows (the registry's terrain in the level's render legend); board colours from `render/ascii-cell-style.js`; vital labels and colours from runtime's HUD model. Each vital reads `current/max (+regen)`, and the `hud` line uses the same form |
| `src/web.mjs` | The browser tab (`--web`): a local `node:http` server running the same game, the screen's ANSI turned into HTML, keys posted back |
| `src/watch.js` | Watching a recorded run: the tick cursor and help toggle over the runtime run viewer |
| `src/levels.js` | Finds and parses SimConfig + InitialState artifact pairs, and a recorded run's tick frames |
| `levels/` | Bundled levels, as `<name>.sim-config.json` + `<name>.initial-state.json`, generated from `levels/recipes.json` |

The simulation side is `packages/runtime/src/runner/play-session.js`: `await createPlaySession(...)`, then `switchTo(actorIdOrLabel)` to seat a party member, `await act(command, { actorId? })` with commands such as `{ kind: "move", params: { direction, sprint? } }` (`sprint: true` takes two tiles, #437), `act({ kind: "wait" })`, `act({ kind: "equip_affinity", params: { affinityKey, replaceKey?, stacks?, intensity? } })`, `act({ kind: "unequip_affinity", params: { affinityKey } })`, `act({ kind: "cast_affinity", params: { targetId, affinityKey? } })` (or `params: { target: { x, y }, affinityKey? }` at a tile: it travels the line and hits the first actor or wall, #461), `act({ kind: "raise_barrier", params: { target: { x, y }, affinityKey? } })` (a push raising barriers, #460) or `act({ kind: "take", params: { targetId, holdingId } })`, then `view()` (including `player.affinities`, `player.affinitySlots`, `player.equippedAffinityKeys`, `player.exhaustedAffinityKeys`, `player.equippedAffinityStacks`, `player.equippedAffinityIntensity` (slots run below the range or intensity held), `player.castableAffinities` (each equipped push or pull with its reach), `player.maxAffinitySlots` and `loot`) and `status()`; `viabilityReport` is the Configurator's list of actors below the viability floor. One command, one closed tick, one fresh frame. Core decides whether a move is legal, whether the actor reached the exit, when it leaves, and whether it is defeated: `status()` is `{ tick, exited, atExit, defeated }`, and once the player is defeated the session refuses every command (reason `defeated`) and runs no more ticks.

## Other actors and traps

The play session's rows draw the terrain, barriers (`B`) and the player (`@`). Other actors (`view().actors`) are drawn on top with the same letters as `ak tick`'s ASCII snapshot: `D` for a delver, `W` for a warden (read from the role, or the id when a generated level leaves the role unset). Traps are the level's hazard actors (`view().hazards`), drawn as `H` under any actor. A trap's field hurts whoever stands in it each turn, so an `emit` trap costs the vital its affinity targets, spilling into health once that is empty (`docs/affinity-table.md`), and it pays `2 + range + intensity²` mana a turn to stay on. Whether actors move is the play session's business, not this package's.

## Bundled levels

Every bundled level is `ak create` output: the Configurator lays out the rooms and corridors and places the actors and traps. `levels/recipes.json` holds each level's `ak create` arguments; regenerate with `pnpm run levels:ascii`, and `pnpm run levels:ascii -- --check` (also a test) fails if a checked-in file drifts from what `ak create` makes. To add a level, add a recipe and regenerate; file names sort into play order, and `tests/ui-ascii/ui-ascii-game.test.js` checks that every bundled level is winnable.

| Level | Recipe |
|---|---|
| `first-steps` | one small room |
| `long-way-round` | three large rooms |
| `warden-hall` | two large rooms. One warden wanders at random; the Configurator posts it on the exit's approach, so the exit opens once it moves. The other attacks: it equips its push and casts at you whenever you are in reach, so you can lose here (r restarts the level). Which affinity each warden holds is just this level's data; any affinity works the same way |
| `trap-rooms` | three small rooms, three `emit` traps of different affinities (fire, water, decay); any affinity works the same way |

Tests that need an exact board shape use the hand-written levels in `tests/fixtures/ui-ascii/levels/`.

**Phone app (PWA).** The same game on a phone, with no server: `packages/ui-ascii/src/browser.js` runs this package's game controller (`game.js` over the runtime play session) in the page, with touch keys, fog on, the game kept on the device, and a **Report** that writes the same markdown `scripts/game/playtest.mjs` does (findings, final screen, replay code), so `bash scripts/game/playtest.sh --open <report.md>` replays a tester's game. A static host cannot run `ak create`, so `node scripts/pwa/build-pwa.mjs` (`pnpm run build:pwa`) builds every playtest scenario ahead of time, seeds 0-11 each (seed N is seed N in `playtest.sh`), through the same `ak create` arguments, so the Allocator prices every level; esbuild bundles the app; the output is `dist/pwa/` (a service worker caches it for offline play). `.github/workflows/pwa-pages.yml` publishes it to GitHub Pages on every push to main (one-time: Settings → Pages → Source: GitHub Actions). The page never reaches the analysis console (#500), which stays in `web.mjs` behind `--debug`. `html.js` (ANSI to HTML) and `report.js` are shared and free of Node built-ins. **Your own character on the phone (#557).** A scenario's brief has *Configure your own delver*: the same character sheet as a tappable screen (tap an affinity or form to step it, each slot showing its mana per tick or per cast, kinds running none → each kind → none; tap a held slot's range or intensity to step it up, looping back to 1 past its limit, shown under the value as `max 7`: the largest value whose mana still fits max mana and whose price still fits the allowance; tap a vital, then − + −5 +5, which do nothing on a choice; boxes keep fixed widths; Play), priced by the Allocator against the level's delver allowance. Play builds the level on the phone from the scenario's `ak create` arguments with your delver in them, by `ak create`'s own code (runtime `commands/author-level.js`); the one part a phone cannot run, z3's object placement, is answered from what z3 decided when the level was built (`AK_SOLVER_RECORD`, replayed by adapters-web's `solver-recorded` adapter), so the level is byte for byte what `playtest.sh --character` builds. Each level file carries its arguments, the default delver, the allowance and those answers. `scripts/pwa/app-entry.js` is the composition root that hands `browser.js` the builder, so this package still imports runtime only. The saved game and the report keep the character, so Resume and `playtest.sh --open` rebuild it.

**Phone layout and updates (#552).** The game screen is a stack of fixed-height bands, so nothing moves while you play: a square board (sized once from the screen; its text is fitted to the level), vitals, a message band that scrolls (what just happened, the open panel in touch words, what is in sight), the affinity slots as buttons (kind, expression, range and power, and `reach N` for a push or pull or `ON`/`drained` for emit and draw; one tap on a held push or pull aims it, an empty slot opens a picker of the affinities you know, and the steppers under the slots run the selected one lower or higher, a turn as in the terminal), and one controls band: the pad (which moves the aim while aiming) with Take / Sprint / More, or Cast / Next target / Cancel while aiming, or the list's buttons for loot, orders and the equip list. The controller supplies it: `game.screen({ parts: true })`, `slots()`, `toggleSlotAffinity()`, `tuneSlot()` and `panelChoices()` in `game.js`. The controls hide for a keyboard (first key pressed, or a fine pointer). The build writes `version.json` (never cached) and bakes its commit into the bundle: the page shows `You are on build <commit>` and a banner when the live build differs (checked on open, on return to the tab and every five minutes); Update clears the cached files and reloads, and the saved game stays as Resume.
